Component set

Every class and element the companion ships, one live specimen each. Nothing on this page is a drawing of a component: each row renders the real markup with the real components.css. Narrow the window to 320 px, and switch Theme in the bar, to check both.

Read this before judging a specimen. Ordering: structure first, then the pieces that carry the most meaning. Contrast, focus and control boundaries below are WCAG 2.2 AA and are asserted in tests/contrast.test.ts, not eyeballed.

Elements

vc-chart element

Bar chart from data. Values are text, so the reading does not depend on bar length or color. Small values keep a 2 px stub instead of vanishing.

vc-tabs / vc-tab element

Authored states, one visible at a time. active is 1-based; data-state is flat JSON of strings. Without JavaScript the first panel still shows.

Nobody owns this yet. The panel is a plain container, so any component can sit inside it.

Owned by payments. Two approvals are required before merge.

Shipped on Tuesday. The migration ran once and was not replayed.
vc-scrub element

Position control over a vc-tabs. Arrow keys, Home and End work; the state name is announced through aria-valuetext, not just a number.

vc-inspect element

Reads the current panel's data-state as a table. A value that changed from the previous position gets a text badge; with no state declared it renders nothing.

What to check while reviewing. Tab through the page: every control shows a 2 px accent ring that the sticky bar never covers. Switch Theme: hover tints lighten on dark instead of darkening. Narrow to 320 px: the table scrolls inside its own region, and nothing pushes the page sideways.
