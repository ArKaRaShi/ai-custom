How much chrome should code, scrub and inspect carry?

The same three components at three levels of structure. Judge the direction, not the pixels: everything below is static markup, so what you see is the shape, not a finished behaviour. Pick per row in chat if one row breaks the pattern.

The complaint is structural, not cosmetic. Today these three are a bordered box with a floating button, a form control between two text buttons, and a table with an unstyled caption. All three read as a widget dropped on a page rather than part of one surface.

Remove the boxes and the pills. Structure stays exactly as it is; only the frames come off, and changed values show as an old-to-new delta instead of a badge.

Every state is a target. The scrub becomes a segmented stepper where each state is a labelled button, code gains a line-number gutter, and the inspector collapses to a row of key-value chips.

B as the default, C for the scrub only. The scrub is the one genuinely dated piece — a slider is the wrong control for two or three named states — so it takes the stepper. Code and inspect only need their frames named, and a full header on every snippet would be heavier than the snippet. Reverse it if state lists routinely exceed six, or if screens are mostly one-line commands: then A wins and you delete the headers again.
