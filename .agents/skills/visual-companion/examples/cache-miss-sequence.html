What happens on a cache miss

A miss costs one extra trip, to the database, and fills the cache so the next request is a hit. In this example, the database read is almost all of the wait.

All timings are illustrative.

The cache is asked first because it is much faster than the database. A miss sends the API on to the database.

Select the client, then choose What this feeds to mark the API, cache and database. What feeds this finds nothing: reply lines run back to the client, but a reply is not a dependency.
