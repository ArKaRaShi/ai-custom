# Architecture rationale

Record each of the following with the design:

1. **Problem and constraints:** what must change and the existing contracts the change must preserve.
2. **Caller usage:** realistic examples written before the type sketch.
3. **Design:** core data, interfaces, module boundaries, invariant ownership, validation and interface depth.
4. **Synthesis decision:** which candidate is the base, what was adopted from others and what was rejected.
5. **Tradeoffs and alternatives:** distinct designs considered, what each exposes to callers and why it lost.
6. **Open questions and risks:** unresolved decisions phrased as questions.
7. **Next implementation step:** the first concrete change against the design.
