Go + Bun only, with two scopes

Everything below was run on this Mac (Bun 1.4.2, Biome 2.5.15, TypeScript 7.0.2, Go 1.27.1). Nothing is written into your skills yet.

1. What changes versus the current plan

Removed
  • Python starter: assets, recipe, 8 acceptance tests, spec section, plan Task 2
  • pnpm and npm recipes and tests (Bun is the only package manager)
  • The per-skill node_modules copy (about 94 MB each)
Kept / new
  • TypeScript on Bun + Biome + tsc
  • Go with only the toolchain: gofmt, go vet, go test
  • Scope 1 (global) and Scope 2 (per skill), below

2. The two scopes, as files on disk

~/.agents/skills/
├── package.json      SCOPE 1 (global, TypeScript): Biome + TypeScript + @types/bun, declared once
├── biome.json        "root": true : shared lint and format rules
├── tsconfig.json     shared compiler settings (Bun types)
├── node_modules/     94 MB, measured, shared by every skill
│
├── notes-ts/           inherits everything: only index.ts + tsconfig.json (extends ../tsconfig.json)
├── strict-ts/          SCOPE 2 (override): adds biome.json {"root": false, "extends": "//", ...}
│    measured: tabs instead of spaces, noExplicitAny off. Same skill folder, 0 extra MB
└── sync-go/            SCOPE 2 (own toolchain): only go.mod + main.go. Never touches the root
     measured: go vet ok, gofmt clean, 2.4 MB binary, no node_modules, no setup

3. What "different rules" can mean, per language

Inherit globalOverride rules (same version)Own dependencies (different version)
TypeScript Nothing extra. Measured: root any rule flagged bad.ts. Child biome.json with extends "//". Measured: passes with any and tabs while the sibling still fails. Biome version stays the root's. Child package.json + its own node_modules (about 94 MB). Only way to pin another Biome or tsc.
Go No global layer. The toolchain on PATH is the shared part. Not configurable: gofmt has no config file. A different rule = different flags in that skill's check command, or adding golangci-lint (not installed here). go.mod is the whole per-skill scope. Its go line pins the language version.
Two corrections to the research, both measured here.
1. TypeScript 5.9.3 is stale. Latest published is 7.0.2. Pin the root to it; paths works but baseUrl does not in 7.
2. "recommended": true in the research's biome.json is deprecated in Biome 2.5. Use "preset": "recommended". Also biome lint --write does not format; the check command is biome check.

4. Rule for which scope a skill is in

Nearest file wins, no registry. Skill has go.mod → Go, standalone. Has biome.json with "root": false → TypeScript override. Has its own package.json → TypeScript standalone. Has none of those → TypeScript inheriting the global root.
