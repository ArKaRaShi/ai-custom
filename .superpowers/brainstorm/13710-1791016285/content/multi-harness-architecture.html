Universal Multi-Harness Architecture

Supporting OMP, Claude Code, Cursor, OpenCode, and any future AI coding tool seamlessly

First-Principles Insight: The "Target" Abstraction

Hardcoding "omp" into the schema makes the same mistake as v2. An AI developer uses multiple tools across different machines:

OMP (~/.omp) Claude Code (~/.claude) Cursor (~/.cursor) OpenCode (~/.opencode) Agent Skills (~/.agents)

👉 Every tool is simply a Target Workspace that contains resources (rules, skills, configs).

manifest.json (Shared in Git) 
{
  "version": 3,
  "targets": {
    "agents": {
      "repoRoot": ".agents",
      "skills": {
        "deep-research": { "origin": "authored" },
        "archify": {
          "origin": "external",
          "install": "npx -y skills add tt-a1i/archify -g"
        }
      }
    },
    "omp": {
      "repoRoot": ".omp",
      "rules": true,
      "agents": true,
      "hooks": true,
      "configs": ["mcp.json", "models.yml"]
    },
    "cursor": {
      "repoRoot": ".cursor",
      "rules": true
    },
    "claude": {
      "repoRoot": ".claude",
      "configs": ["settings.json"]
    }
  }
}
locations.json (Local to THIS Machine) 
{
  "version": 3,
  "targets": {
    "agents": "~/.agents",
    "omp": "~/.omp/agent",
    "cursor": "~/.cursor",
    "claude": "~/.claude"
  },
  "excludes": [
    "omp/config.yml",
    "claude/credentials.json"
  ]
}

/* 100% 1:1 match:
   targets.omp <--> targets.omp
   Excludes are naturally scoped:
   "<target-id>/<relative-path>" */

Why This Scales Indefinitely

  • Universal 1:1 Keys: manifest.targets[id] maps cleanly to locations.targets[id]. Zero mismatch.
  • Crystal-Clear Exclusions: excludes: ["omp/config.yml", "claude/local.json"] unambiguously identifies the target and the file.
  • Future-Proof for any AI Tool: Tomorrow if you start using OpenCode, Aider, or Codex, you just add an entry under targets. No rewrites, no schema breaks.
