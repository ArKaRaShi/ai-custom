Collision Safety & Atomic Rename Deep-Dive

Why ~/.local/bin/ai-sync avoids UNIX collisions, and how Atomic Staging prevents torn reads

Part 1: The Collision Catch — sync vs ai-sync

You caught a vital UNIX pitfall: /bin/sync is a 50-year-old native POSIX utility that flushes filesystem cache buffers to disk.

Naming the binary ~/.local/bin/sync could hijack system buffer flushing scripts if ~/.local/bin is first in $PATH!
The Clean Solution:
• Name the binary ~/.local/bin/ai-sync (100% collision-free).
• You can optionally add a shell alias alias sync="ai-sync" in your interactive .zshrc, but the actual binary remains ai-sync.
Part 2: How Option A (Atomic Staging + POSIX Rename) Works Visually
STEP 1: BACKGROUND STAGING

The active folder remains untouched while files download or transfer into a hidden sibling directory:

~/.agents/skills/
├── deep-research/        ← Active (readers use this)
└── .tmp-deep-research/   ← Staging new files
STEP 2: POSIX ATOMIC SWAP

Once all files are verified on disk, a single OS kernel syscall executes in <1 millisecond:

// Node / Bun fs.renameSync:
fs.renameSync(
  ".tmp-deep-research",
  "deep-research"
);
STEP 3: ZERO TORN READS

In the POSIX filesystem table, the directory inode pointer flips instantly:

✔ A running AI agent or LSP either reads 100% old version or 100% new version.
✔ If transfer is killed mid-way, staging folder is deleted and active skill is never corrupted!
