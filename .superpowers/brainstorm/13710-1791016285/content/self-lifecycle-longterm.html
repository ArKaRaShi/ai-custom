The Self-Hosting Lifecycle Paradox: Long-Term Architecture

How ai-sync upgrades itself across multiple machines without breaking or requiring ad-hoc fixes

The Problem: A Tool Synchronizing Its Own Source Code

When you update ai-sync on your Mac (v2 ➔ v3) and push to GitHub:

  1. Your other PC pulls the Git repo (so ~/Disk/ai-custom has the v3 code).
  2. But in your PC's ~/.agents/skills/ai-sync/, the installed tool is still running the old v2 code!
  3. When you type sync on that PC, the old v2 binary wakes up, tries to parse the new v3 manifest, and crashes. It can't even run the pull command to upgrade itself.

👉 This is the exact problem Homebrew, Rustup, and Git had to solve: self-bootstrapping.

RECOMMENDED (HOMEBREW / RUSTUP STYLE)

Pattern 1: The Immutable Trampoline Runner

A 10-line wrapper that checks for self-updates before running

# ~/.local/bin/sync or shell function:
sync() {
  # 1. If repo has a newer ai-sync, fast-copy it first:
  if [ "$REPO/ai-sync" -nt "$LOCAL/ai-sync" ]; then
    cp -R "$REPO/ai-sync" "$LOCAL/ai-sync"
  fi
  # 2. Execute the engine (always runs latest code):
  bun "$LOCAL/ai-sync/scripts/sync.ts" "$@"
}

Why this is a permanent solution

  • Zero chicken-and-egg: The wrapper checks the repo file mtime before TypeScript even loads.
  • Works across breaking versions: Even v2 ➔ v10 will never crash because the engine is updated before execution.
  • Standard practice used by Homebrew (brew.sh) and Cargo.
ALTERNATIVE (GO / CHEZMOI STYLE)

Pattern 2: Run Directly from Backup Repo

Eliminate the two-copy problem entirely for ai-sync

# ai-sync is never copied to ~/.agents/skills/ai-sync
# It lives ONLY in ~/Disk/ai-custom/

alias sync="bun ~/Disk/ai-custom/.agents/skills/ai-sync/scripts/sync.ts"

Why this works

  • Whenever Git pulls, the tool is instantly the latest version.
  • No copying, no sync lag, no chicken-and-egg paradox.

Trade-off

  • ai-sync does not live in ~/.agents/skills, so it cannot be inspected as a regular local skill by OMP unless symlinked.
ALTERNATIVE (RUSTUP / NPM STYLE)

Pattern 3: In-Process Re-Execution

TypeScript engine updates itself before reading manifest

// Top of sync.ts, before any manifest parsing:
if (isRepoSelfNewer(repoBase)) {
  copySelfFromRepo(repoBase);
  // Re-spawn process with the newly copied script and exit:
  Bun.spawnSync([process.argv0, ...process.argv]);
  process.exit(0);
}

Why this works

  • Contained entirely in TypeScript; no shell script or wrapper needed.

Trade-off

  • Only protects future updates (v3 ➔ v4), but requires one-time bootstrap to get from old v2 ➔ v3.
