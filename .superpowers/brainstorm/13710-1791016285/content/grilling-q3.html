🔥 Question 3: Partial Target Failures & Transaction Boundaries

A sync operation covers multiple targets: agents, omp, cursor, claude.

Suppose Target 1 (agents/skills) copies successfully, but Target 2 (omp) fails halfway through due to a file permission issue or locked socket.

Should the entire sync transaction roll back and undo Target 1, or should Target 1 stay synced while Target 2 reports an error?

RECOMMENDED (BEST-EFFORT PER TARGET)
A

Isolated Target Transactions + Summary Report

Successful targets stay synced; failures exit code 1

  • Each target is an atomic unit. If agents succeeds, it commits.
  • If omp fails, its staging folder is rolled back without corrupting omp.
  • CLI exits with code 1 and clearly lists:
    ✔ agents: 4 skills synced
    ✖ omp: permission denied on hooks/notifier.ts (aborted)
  • Next time you run sync, it only needs to sync the remaining omp files!
B

Global Multi-Target Rollback (All-or-Nothing)

Undo everything if any target fails

  • If any target fails, restore backups for all preceding targets to leave zero changes on disk.
  • Trade-off: Highly complex two-phase commit logic; if rollback itself fails, leaves system in an unknown partial state.
C

Interactive Halt on Error

Pause terminal and ask what to do

  • Pauses terminal: [r] Retry [s] Skip this target [a] Abort.
  • Trade-off: Breaks automated agent scripts and background syncs.
