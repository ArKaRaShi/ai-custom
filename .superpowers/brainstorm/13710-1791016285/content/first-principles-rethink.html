The Old Flawed Model (Roots & Path Globs)

Treated everything as two artificial "roots" (omp path root vs agents skill root). Forced complex syntax:

$ sync track path extensions --root omp --sync
$ sync track path extensions/orca-* --root omp --no-sync
$ sync track skill mentor --root agents --origin authored

✖ Verbose, unintuitive, and constantly confusing about what belongs where.

Rethought: Declarative Workspace Modules

First-class awareness of AI modules. Natural, clean commands:

$ sync add skill my-skill
$ sync add rule ts-no-any
$ sync add agent sonic
$ sync ignore config.yml --local

✔ Clean nouns that match what you actually build.

How Multi-PC Configuration Works Cleanly

1. Shared by Default (All your PCs get them)

Your tools and standards should be identical everywhere:

  • All your skills (deep-research, skill-framework, etc.)
  • All your rules (coding standards, formatting)
  • All your agents (custom subagents)
  • All your hooks (safety guards)
  • Shared mcp.json (Context7, TablePlus)

2. Machine-Specific Overrides (This PC only)

Hardware, GPU, and local credentials stay isolated:

  • Local models: Mac uses Apple Metal / local Ollama; PC uses Nvidia CUDA.
  • config.yml: Each machine has its own model routing.
  • How it's controlled:
    sync ignore config.yml --local (Private to this machine)
    OR
    hosts/macbook/config.yml (Each PC backs up its own config in Git).
