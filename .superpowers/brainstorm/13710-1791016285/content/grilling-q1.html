Grilling Session: Stress-Testing ai-sync v3 (Question 1 of 5)

5 critical stress-test questions before implementation. Here is Question 1:

🔥 Question 1: The Multi-Machine Upgrade Paradox (Chicken-and-Egg)

Because we are doing a clean break with zero backward compatibility:

When you push the new v3 manifest (manifest.json version 3) from this Mac to GitHub, your other PCs still have the old v2 ai-sync script installed in their local folders.

When you sit at your other PC and run sync pull, the old v2 script will see the new v3 manifest, fail to parse it, and crash before it can even pull the new v3 code!

RECOMMENDED (OPTION A + B)
A

Tool-First Self-Update + 1-Liner Bootstrap

Automatic self-upgrade with fallback

  • sync pull detects if ai-sync itself is newer in the repo and copies the new engine first.
  • For old machines that crash, we document a simple 1-line manual bootstrap:
bun ~/Disk/ai-custom/.agents/skills/ai-sync/scripts/sync.ts bootstrap --apply
B

Pure Manual Git Pull on Other PCs

No self-update code inside the tool

  • You explicitly run git pull inside ~/Disk/ai-custom on other PCs.
  • Then copy the updated skill to ~/.agents/skills/ai-sync once.
  • Zero magic, but requires manual intervention on each PC.
C

Temporary Transition Guard in v2

Patch the existing v2 code before pushing v3

  • We push a quick commit that teaches v2: "If version === 3, auto-run the v3 script".
  • Guarantees existing v2 clones on other PCs gracefully transition.
