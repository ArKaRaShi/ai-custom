The Generic Interface: SyncModule

To add any new resource in the future, you implement just ONE interface. The core engine never needs to change: 

export interface SyncModule {
  readonly id: string;               // e.g. "skills", "rules", "configs"
  readonly defaultLocalPath: string; // e.g. "~/.agents/skills"
  readonly defaultRepoPath: string;  // e.g. ".agents/skills"

  // 1. Inventory: find all items of this kind
  scan(directory: string): Promise<ResourceItem[]>;

  // 2. Versioning: compute version & hash (no manual inspection needed!)
  getVersion(item: ResourceItem): Promise<VersionInfo>;

  // 3. Transfer: how an item moves to/from disk
  export(item: ResourceItem, repoDir: string): Promise<void>;
  import(item: ResourceItem, localDir: string): Promise<void>;
}

How Adding Future Resources Works in Practice

  1. Need to sync Cursor rules tomorrow? Create modules/cursor.ts implementing SyncModule. Done.
  2. Need to sync system shell dotfiles? Create modules/dotfiles.ts. Done.
  3. Zero changes to the CLI or sync engine: sync status, sync push, and sync pull automatically discover and sync the new module.
