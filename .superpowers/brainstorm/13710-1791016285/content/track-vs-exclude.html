track vs exclude: How They Differ

The boundary between shared repository policy and machine-local privacy

SHARED REPO POLICY (GIT)

sync track / untrack <skill>

"What skills exist in my ecosystem?"

Where it's saved:
<repo>/.ai-sync/manifest.json
✔ Committed to Git · Shared across ALL PCs/Macs
What it does:
  • Adds a skill (e.g. deep-research) to your backup.
  • Every machine that pulls this repo gets the skill.
  • For external skills, stores the installer command so any machine can bootstrap it.
$ sync track deep-research
✔ Registered 'deep-research' in .ai-sync/manifest.json
MACHINE-LOCAL PRIVACY (THIS DEVICE ONLY)

sync exclude add/rm <root> <path>

"What should Git ignore on THIS specific machine?"

Where it's saved:
~/.config/ai-sync/locations.json
✔ Stays on THIS Mac · NEVER committed to Git
What it does:
  • Prevents local files (e.g. omp /config.yml) from being synced or overwritten.
  • Your Mac keeps its local settings/models intact.
  • Other PCs/Macs continue tracking that file normally in Git!
$ sync exclude add omp /config.yml
✔ Excluded 'omp:/config.yml' on this machine only
Summary Comparison
Dimension sync track sync exclude
Scope Global (All devices) Local (This workstation only)
Git Status Committed to Git repo Never committed (in ~/.config)
Granularity Whole skill package (e.g. deep-research) Specific file/path (e.g. /config.yml)
Use Case "Add this skill to my shared backup" "Don't overwrite my Mac's local config during sync"
