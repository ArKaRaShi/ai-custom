🔒 Question 5: Secret Leakage & Private Config Guardrails

In an AI developer workspace, local files often contain API keys, tokens, and private credentials:

  • ~/.omp/secrets.env (OpenAI, Anthropic, Gemini API keys)
  • Local proxy tokens in config.yml
  • Private .env files inside custom skills or hooks

When an agent or user runs sync push --apply --git, how does ai-sync guarantee that private credentials NEVER get pushed to GitHub?

RECOMMENDED (MULTI-LAYER SECRET SHIELD)
A

Pre-Flight Secret Scanner + Hard Block

Automated pattern checks halt before Git commit

  • Layer 1 (File patterns): *.env, secrets.*, *credential*, id_rsa* are banned by default.
  • Layer 2 (Secret scanner): Scans text for high-risk token signatures (sk-proj-, ghp_, AIzaSy, Bearer ).
  • Hard Stop: If a secret is detected, sync push immediately aborts with non-zero exit code:
    ✖ ABORTED: Potential API key detected in 'config.yml'. Use 'sync ignore config.yml --local' to protect it.
B

Manual User Responsibility

Rely solely on user's manual ignore rules

  • No automated scanners. If a user forgets to run sync ignore, the file is pushed.
  • High risk: Accidental key leak on GitHub leads to revoked credentials or unauthorized API spend.
C

Interactive Warning Prompt

Ask user to confirm on detected secret

  • Prompts: [y/N] Potential key found. Push anyway?
  • Trade-off: Dangerous if typed reflexively, and blocks unattended agent tasks.
