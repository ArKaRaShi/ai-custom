ai-sync v3: Architectural Approaches

Comparing 3 clean-break architectures to eliminate complexity and conflict pain

RECOMMENDED
1

Package Manager Model

Skills as cohesive versioned packages (Cargo / Homebrew style)

• SKILL.md version + Merkle tree hash
• Automatic high-level [▲ LOCAL] [▼ REPO] preview
• Safety snapshots in ~/.config/ai-sync/backups/

Why this wins

  • Zero manual inspection: Status prints exact upgrade/downgrade verdicts per skill.
  • Deletes ~60% legacy code: Drops v1/v2 path glob complexity and raw text merge.
  • Safety first: Snapshot backup before any overwrite guarantees zero lost edits.

Trade-off

  • Clean break: requires a clean new v3 manifest schema.
2

Git-Native Tree SHA Model

Track Git tree object IDs directly

• Tracks commit SHA + git ls-tree hashes
• Delegates versioning entirely to Git history

Pros

  • No version strings needed; Git commits define history.

Cons

  • Local directories (~/.agents/skills) are not Git repos, requiring complex temporary git index queries.
3

Sync Journal & Ledger

Append-only transaction log across machines

• .ai-sync/journal.jsonl records every push/pull
• Vector clocks track causality

Pros

  • Full audit log of every change across all devices.

Cons

  • Over-engineered for personal backup; journal compaction and clock drift management.
