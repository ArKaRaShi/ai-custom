Can I switch from Bun install to pnpm later?

Yes. Keep the dependency manifest and quality configs. Approve the manager switch, regenerate the dependency resolution with pnpm, replace the old lockfile intentionally, and rerun checks and behavior tests. Versions or lifecycle behavior can differ, so a manager switch is not assumed equivalent.

Can I use Node instead of Bun?

Yes, as a runtime adaptation. Update the runtime requirements and real execution/test scripts. Preserve existing Node tooling instead of forcing Bun. The initial copyable starter targets Bun; no Node starter is claimed implemented.

pyproject.toml is the source for the dev dependency group and both tools' settings. Avoid maintaining duplicated dev-tool lists in both TOML and requirements files.

uv

Approved setup resolves dependencies and produces uv.lock. Subsequent reproducible setup uses the lock. Run installed tools from .venv after setup so checking does not silently sync or download packages.

pip inside .venv

Create the environment explicitly with python -m venv .venv. A pip version supporting dependency groups can install the same dev group with .venv/bin/python -m pip install --group dev. Document the required pip version and Windows command equivalents. A dependency-group install is not a transitive lock: use a reviewed pinned snapshot or documented locking procedure for repeatable installs.

Other existing manager

Keep an existing supported manager and lockfile. Adapt only the setup/runner instructions. Poetry or another manager may require a dependency-group translation; do not claim every manager accepts the same TOML syntax.

Quality checks remain pyright, ruff check ., and ruff format --check .. Their installation path changes, not their purpose.

Pyright uses Node.js internally. Document that prerequisite and the Python wrapper's provisioning behavior. Setup needs approval; checking should not bootstrap a missing runtime.

Selection and adjustment rules

SituationDecision
Existing skillReuse its runtime, manager, lockfile, and quality setup. Merge missing checks; never overwrite blindly.
New skillHonor the user's choice. Suggested defaults: TypeScript + Bun + Biome; Python + uv + Pyright + Ruff.
One lockfileUse its manager. Missing manager means report setup requirements; do not fall back and generate a competing lock.
Conflicting lockfilesAsk which manager owns the skill before installation.
Mixed-language skillCombine only the necessary language profiles, each with its declared scope and environment.
Documentation-only skillKeep documentation/metadata/link checks. No code starter or empty package manifest.

No extra profile registry or generator. Existing manifests, lockfiles, tool configs, and the skill's Verification section record the choices. Copied configs belong to the consuming skill; nothing imports the framework at runtime.
