How Versioning Works in ai-sync v3 (Full Visual Guide)

Two-tier detection: Human SemVer when declared + Deterministic Merkle Tree Hash as safety net

TIER 1: HUMAN SEMVER

SKILL.md Frontmatter

Standardized open spec (agentskills.io):

---
name: deep-research
version: "1.2.0"
description: ...
---

• Easy for humans and agents to read.
• If omitted, defaults safely to "0.0.0".

TIER 2: MERKLE TREE HASH

12-Char Directory Fingerprint

Deterministic content digest of the whole skill:

deep-research/
├── SKILL.md         (hash content)
├── scripts/run.ts   (hash content)
└── references/      (hash content)
➔ Tree Hash: "9a2f7c41e80b"

• Automatically excludes node_modules/ & .venv/.
• Any changed character instantly changes the hash.

The 4-State Verdict Decision Matrix
Local vs Repo Version Tree Hash Check Verdict Badge What ai-sync Does
v1.2.0 == v1.2.0 Hashes Match [✔ IN SYNC] Nothing to do. Both sides are identical.
v1.3.0 > v1.2.0 Hashes Differ [▲ LOCAL NEWER] Safe Push: exports newer local version into repo.
v1.1.0 < v1.2.0 Hashes Differ [▼ REPO NEWER] Safe Pull: imports newer repo version into local machine.
v1.2.0 == v1.2.0 Hashes Differ! [✖ CONFLICT] Both sides modified code at v1.2.0 without bumping. Run sync resolve <skill> --ours|--theirs.
