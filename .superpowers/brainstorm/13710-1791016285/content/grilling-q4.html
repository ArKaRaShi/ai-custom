🔥 Question 4: External Dependency & Offline Failure Handling

When running sync bootstrap on a fresh machine (or provisioning in an environment with flaky Wi-Fi):

All your authored skills, rules, and agents copy from Git with 100% success. But an external skill fails to install via its command (e.g. npx -y skills add anthropics/skills/frontend-design -g fails due to npm registry timeout).

Should bootstrap halt immediately and leave the machine half-installed, or continue and provide an actionable retry recipe?

RECOMMENDED (CONTINUE + COPYABLE RETRY)
A

Non-Blocking Continuation + Actionable Retry

Finish all reachable files; report exact retry commands

  • All authored skills, rules, agents, and configs finish installing so your machine is immediately usable.
  • Failed external tools are logged with exact failure output and exit code 1.
  • At the end of bootstrap, prints a copyable one-line command to retry:
    To retry failed external skills: sync bootstrap --retry-external
B

Strict Abort on First Error

Halt immediately when any command fails

  • Fails fast, but leaves the user with a partially configured machine and no working tools.
C

Automatic Retry Loop (3 Attempts)

Retry with exponential backoff

  • Retries 3 times before failing.
  • Trade-off: If the user is offline or npm registry is down, causes a 45-second freeze waiting for network timeouts.
