Language starters, copied into each skill

Proposal only. Keep the verification contract generic; supply concrete, tested starter files for each supported language. No starter files have been implemented.

│           └── .gitignore           ← environments/caches
└── tests/
    └── starter checks              ← isolated valid/invalid fixtures

assets/ contains files to copy. references/ explains their use. primitives/ contains reusable contracts, not language-specific configuration.

Choose matching starter→Copy into new skill, or merge existing config→Approve installation→Generate consumer lockfile + run checks

Copy once, own locally. Consuming skills do not import framework files at runtime. Existing tooling takes precedence; no automatic overwrites, global installs, background migrations, or mass retrofit.

Cover scripts, tests, and executable examples. Start with strict types and correctness rules, not a large collection of stylistic rules. No separate Prettier when Biome covers the code.

Environment: uv for a new starter; respect existing project manager.
Pyright: static type checking.
Ruff: correctness lint and formatting.

OperationInside the prepared environment
Checkpyright
ruff check .
ruff format --check .
document the sequence; no runner framework
Testpython -m unittest discover -s tests
or the existing test runner + changed-path smoke
Fixruff check --fix .
ruff format .
explicit, separate operation

Declare tool versions and check all included Python code. Use strict types and explicit annotations. No pytest dependency unless behavior tests need it.

Pyright prerequisite: its engine uses Node.js. The Python package is a community wrapper and may provision Node. Document that dependency and require approved setup; do not hide network/bootstrap work inside a “read-only” check.

What stays common

Both startersBoundary
Local dev tools, pinned compatible versions, consumer lockfileNo tracking node_modules/, .venv/, or caches
Read-only check; explicit fix; real behavior testNo fake success script or generated placeholder tool
Metadata, layout, Markdown, and local-link verificationDocument required Markdown checker and honest fallback
Document prerequisites, install/recovery, scope, outcomesA missing checker remains an unverified limit

Documentation-only skills keep a documentation verification procedure and can remain SKILL.md alone. Mixed-language skills combine only the required configuration. Consumer lockfiles are generated after merging dependencies, not copied over existing locks.

Acceptance before shipping the starters

Copy each starter into a disposable skill. Confirm valid code passes, a syntax error fails, a type mismatch fails, a correctness defect fails, and formatting drift fails without changing files. Verify the explicit fix affects only its fixture and rerun checks. Record tool versions and outcomes.
