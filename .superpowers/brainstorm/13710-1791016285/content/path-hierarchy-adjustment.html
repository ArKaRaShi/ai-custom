Path & Naming Adjustment: Aligning Manifest with Locations

Resolving the discrepancy between physical disk folders and logical modules

The Discrepancy You Spotted
Why the previous draft was confusing:
  • locations.json defined the root as "omp": "~/.omp/agent"
  • manifest.json defined the modules as "rules", "agents", "hooks", "configs"
  • excludes wrote "configs:config.yml"

👉 Disconnect: In reality, rules, agents, hooks, and configs all physically live inside ~/.omp/agent/!

RECOMMENDED (100% CONSISTENT)

Approach A: 2 Base Workspaces (omp & agents)

Mirror the exact physical folder hierarchy

manifest.json (shared): 
{
  "version": 3,
  "agents": {
    "skills": {
      "deep-research": { "origin": "authored" }
    }
  },
  "omp": {
    "rules": true,
    "agents": true,
    "hooks": true,
    "configs": ["mcp.json", "models.yml"]
  }
}
locations.json (local): 
{
  "version": 3,
  "bases": {
    "agents": "~/.agents",
    "omp": "~/.omp/agent"
  },
  "excludes": [
    "omp/config.yml"
  ]
}
✔ omp/config.yml matches the exact relative path in Git and on disk.
✔ Zero ambiguity: everything under omp is organized under omp.
ALTERNATIVE (FLAT)

Approach B: Explicit Module Paths

Declare the full path for each module

locations.json: 
{
  "version": 3,
  "modules": {
    "skills": "~/.agents/skills",
    "rules": "~/.omp/agent/rules",
    "agents": "~/.omp/agent/agents",
    "hooks": "~/.omp/agent/hooks",
    "configs": "~/.omp/agent"
  },
  "excludes": [
    "configs/config.yml"
  ]
}
• Every module is flat, but requires defining 5 paths instead of 2 bases.
