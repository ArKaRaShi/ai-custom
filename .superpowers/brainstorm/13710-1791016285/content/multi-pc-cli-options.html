Multi-PC Architecture: Unified Flags vs Subcommands

Managing several PCs with different configs: how to make tracking & exclusions clean

A

Scope Flags on Unified Verbs

One mental model: everything is track or ignore, scoped with flags

# Share across ALL your PCs (Git manifest):
sync track <skill>  # default: --shared

# Ignore on THIS PC only (local ~/.config):
sync ignore <path> --local

# Check active settings:
sync list [--local|--shared]

Why this is clean

  • Follows git config --global vs --local pattern: familiar to every engineer.
  • No separate exclude add/rm/list mini-CLI: just sync ignore with --local.
  • Eliminates duplicate verbs completely.
B

Machine Profiles (Hosts in Git)

Track all PCs' configs in Git under dedicated host folders

# Repo stores per-machine configs:
.omp/hosts/macbook-pro/config.yml
.omp/hosts/desktop-pc/config.yml

# Machine selects its identity once:
sync profile use macbook-pro

Why this is powerful

  • Nothing is lost: even machine-specific configs are backed up in Git!
  • No manual exclude rules needed: each PC maps to its own host folder in the repo.
C

Single-Verb `sync` with Modifier Flags

One command does everything via flags

sync --track <skill>
sync --ignore <path> --local
sync --push --git
sync --pull

Trade-off

  • Only sync binary, but flags get long and easy to mistype.
