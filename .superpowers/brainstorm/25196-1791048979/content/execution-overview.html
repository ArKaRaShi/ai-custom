ai-sync v3: the overall picture

What gets built, how it is shaped, who builds it. Nothing runs until you say go.

1. The shape: four layers, one wiring file

Imports point down only. Checked by layer-guard.ts
cli.ts (composition root): builds objects, runs ONE use case, prints. No decisions.
presentation/: parse args, render tree or JSON
application/: use-cases (one class, one execute) + services (TransferRunner) + interfaces
infrastructure/: NodeFileStore, git adapter, config files, installer, snapshots, 5 resource modules
domain/: pure rules. versioning, schema, secrets, paths, errors. No I/O.

2. What you get when it is done

Commands
status / push / pull (preview by default, --apply to write)
resolve (snapshot first, then ours/theirs)
bootstrap (fresh machine restore)
init / add / remove / ignore
Safety
Atomic rename, no torn reads
Rollback per target
Secret scan blocks push
Per-machine excludes
Overlapping paths rejected
SemVer + hash verdicts

3. The 12 tasks, in order

Foundation (1-3): entities + errors, pure rules, file store + fake
Adapters (4-6): resource modules, config/git/excludes, atomic installer + snapshots
Core (7-9): PlanSync, push/pull + TransferRunner, resolve/status/bootstrap
Surface (10-11): manifest edit commands, CLI + end-to-end smoke
Cutover (12): trampoline, delete legacy files, SKILL.md, final review

4. Who does what (per task loop)

me: write task brief from plan
  → scout (read-only): map files the task touches, report conflicts
  → sonic: write failing test, implement, run tests, report
  → me: check diff + run tests myself
  → reviewer: spec + quality check
  → fix loop if needed, then record in progress.md, next task
end: whole-branch reviewer pass, then full suite + layer-guard

Per your instruction: sonic and scout run with the @free model override. Reviewer uses the default model. Tasks run one at a time (each builds on the last).

5. Where code goes, and what stays untouched

Written
New layered files in ~/.agents/skills/ai-sync/scripts/ and tests/.
Old flat files deleted only in Task 12.
Not committed
Spec and plan stay uncommitted in ~/Disk/ai-custom.
Skill dir is not a git repo, so no commits there either.
